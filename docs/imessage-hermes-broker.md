# iMessage Hermes Broker

This Mac-side broker exposes a small HTTP API for moving iMessage text and
attachment context through Hermes to the Rabbit gateway, then sending Hermes or
Rabbit responses back through macOS Messages.

It is dry-run by default. It never runs Rabbit device commands, never exposes
Rabbit relay tokens, and does not send iMessages unless
`IMESSAGE_BROKER_ALLOW_SEND=true`.

For Rabbit Creation use, Hermes is the security and verification front door.
The hosted Creation is prefilled with the Hermes verifier URL and the tailnet
iMessage broker URL, but it never includes the broker token. Hermes verifies the
caller, reads `/private/tmp/imessage-hermes-broker-token.txt` locally on the
Mac, injects `x-imessage-broker-token` only on the server-side broker request,
and returns sanitized JSON.

## Start

```bash
IMESSAGE_BROKER_TOKEN="$(openssl rand -hex 24)" \
HERMES_IMESSAGE_UPSTREAM="http://127.0.0.1:9120" \
npm run broker:imessage
```

Default endpoint:

```text
http://127.0.0.1:8796
```

Health:

```bash
curl -H "x-imessage-broker-token: $IMESSAGE_BROKER_TOKEN" \
  http://127.0.0.1:8796/imessage/health
```

The Desktop launcher sets `IMESSAGE_BROKER_REQUIRE_TOKEN=true` by default.
Tokenless tailnet-only reads are supported only when explicitly launched with
`IMESSAGE_BROKER_REQUIRE_TOKEN=false`.

Rabbit/Creation calls should go through Hermes instead of setting the broker
token header directly.

```text
Hermes verifier: https://michaels-macbook-pro.tailcfaeac.ts.net:8443
iMessage broker:  https://michaels-macbook-pro.tailcfaeac.ts.net:10000
```

## API

`POST /imessage/inbound`

Use this for Messages watchers, Shortcuts, or Hermes adapters that capture an
incoming iMessage and need to forward it into Hermes/Rabbit gateway handling.

```json
{
  "requestId": "imsg-in-001",
  "conversationId": "chat-id-or-handle",
  "from": "+15555550100",
  "text": "What is this?",
  "attachments": [
    {
      "id": "att-1",
      "name": "photo.jpg",
      "mimeType": "image/jpeg",
      "path": "/absolute/local/path/photo.jpg",
      "thumbnailPath": "/absolute/local/path/photo-thumb.jpg"
    }
  ]
}
```

`POST /imessage/hermes-response`

Use this when Hermes or the Rabbit gateway has a reply ready for iMessage.
`POST /imessage/send` is the same operation.

```json
{
  "requestId": "imsg-out-001",
  "to": "+15555550100",
  "text": "Rabbit response text",
  "attachments": [
    {
      "name": "diagram.png",
      "mimeType": "image/png",
      "description": "A compact description generated by Hermes."
    }
  ]
}
```

`GET /imessage/messages`

Use this for Rabbit/Hermes polling of new broker-captured iMessage content.
This returns messages that have entered the broker through
`POST /imessage/inbound`; it does not scrape historical Messages.app database
content.

```bash
curl -H "x-imessage-broker-token: $IMESSAGE_BROKER_TOKEN" \
  "http://127.0.0.1:8796/imessage/messages?limit=25"
```

`GET /imessage/threads`

Use this for authenticated read-only retrieval from the local macOS Messages
database. Default shape is the last 15 threads with up to 25 received and 25
sent messages in each thread:

```bash
curl -H "x-imessage-broker-token: $IMESSAGE_BROKER_TOKEN" \
  "http://127.0.0.1:8796/imessage/threads?threadLimit=15&perDirection=25"
```

Response includes:

- `threads[].received`
- `threads[].sent`
- `threads[].lastMessageAt`
- `threads[].chatIdentifier`

The broker opens `~/Library/Messages/chat.db` in SQLite read-only mode. Override
with `IMESSAGE_BROKER_MESSAGES_DB` for tests or alternate storage.

Tokenless GET reads can be enabled for tailnet-only debugging with:

```bash
IMESSAGE_BROKER_REQUIRE_TOKEN=false npm run broker:imessage
```

In that mode, real sends should still require:

```text
x-imessage-broker-token: <token from /private/tmp/imessage-hermes-broker-token.txt>
```

After each poll, store `nextCursor` and pass it back as `since`:

```bash
curl -H "x-imessage-broker-token: $IMESSAGE_BROKER_TOKEN" \
  "http://127.0.0.1:8796/imessage/messages?since=1700000000000-abcd1234&limit=25"
```

## Attachment Policy

- If a small thumbnail is provided and is under
  `IMESSAGE_BROKER_MAX_THUMBNAIL_BYTES`, the broker marks it as preferred.
- If no sendable thumbnail exists, the broker asks Hermes to describe the
  attachment through `HERMES_IMESSAGE_DESCRIBE_PATH`.
- If Hermes is unavailable, the broker falls back to file metadata only.
- Current send mode sends text descriptions. Thumbnail file-send support is
  deliberately isolated behind the same send gate for a later adapter pass.

## Send Gate

To allow real iMessage sends:

```bash
IMESSAGE_BROKER_ALLOW_SEND=true npm run broker:imessage
```

macOS may still require Automation permissions for the terminal runtime that
starts the broker. Leave the broker in dry-run mode until the Hermes/Rabbit
message loop has been tested with non-sensitive contacts.

## Audit

The broker appends local audit entries to:

```text
public/broker/imessage-audit-log.jsonl
```

Set `IMESSAGE_BROKER_STATE_ROOT` to keep runtime audit files outside the tracked
repo, matching the Mac broker state-root pattern.
